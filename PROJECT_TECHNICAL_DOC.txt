一、项目概述 (Project Overview)
================================================================================

Cloud Drive 是一个基于 Next.js 16 App Router 的全栈 Web 应用，集成了以下核心功能:
  - 个人云存储（文件上传/下载/文件夹管理）
  - AI 多模型对话助手（支持联网搜索、长期记忆、思考过程展示）
  - B站视频浏览与播放（弹幕、评论、代理、清晰度切换）
  - 抖音热榜浏览
  - 即时通讯（私聊、群聊、好友系统）
  - 自定义表情包系统
  - 用户会员体系（CDK兑换、黄金会员）
  - 管理后台（CDK管理、用户管理、AI模型管理）
  - 超级浏览器（服务端网页代理）
  - 暗色/亮色主题切换

运行平台:
  - 生产环境: Ubuntu Linux (通过 PM2 管理进程)
  - 部署服务器: HK (38.54.85.8) + CN (106.14.126.214)
  - 数据库: PostgreSQL (生产) / SQLite (本地开发)


二、技术栈 (Technology Stack)
================================================================================

[运行时]
  - Next.js:         16.2.6  (App Router, React Server Components)
  - React:           19.2.4
  - TypeScript:      5.x
  - Node.js:         >=20

[数据库]
  - ORM:             Prisma 7.8 (输出目录: lib/generated/prisma)
  - 数据库适配器:    @prisma/adapter-pg (PostgreSQL连接池)
  - PostgreSQL驱动:  pg (npm包)
  - 本地开发:        SQLite (prisma/dev.db)

[认证]
  - JWT库:           jose 6.2.3 (SignJWT / jwtVerify, 算法HS256)
  - 密码加密:        bcryptjs 3.0.3 (加盐10轮)
  - 传输方式:        httpOnly Cookie (名为 "token", 7天过期)

[实时通信]
  - WebSocket库:     socket.io 4.8.3 (客户端+服务端)
  - 挂载路径:        /api/socketio

[样式]
  - CSS框架:         Tailwind CSS v4 (通过 @import "tailwindcss" 和 @tailwindcss/postcss)
  - 图标:            lucide-react 1.14.0
  - 动画:            CSS @keyframes (fade-in, slide-up, shimmer, cursor-blink, char-appear)
  - 主题:            CSS变量 (--background, --foreground) + .dark class

[B站/抖音集成]
  - DOM解析:         cheerio 1.2.0 + jsdom 29.1.1
  - 网页提取:        @mozilla/readability 0.6.0
  - HTTP客户端:      axios 1.16.0
  - 中继代理:        通过环境变量 RELAY_URL 转发请求到代理服务

[邮件]
  - SMTP库:          nodemailer 8.0.7 (默认QQ邮箱 smtp.qq.com:465)

[文件处理]
  - 文件上传解析:    busboy 1.6.0
  - UUID生成:        uuid 14.0.0

[部署]
  - 进程管理:        PM2
  - 部署脚本:        deploy.ps1 (PowerShell, 通过 plink/ssh)
  - 反向代理:        Nginx (nginx_beautyfun_hk.conf)

[开发工具]
  - TypeScript执行:  tsx 4.21.0
  - 代码检查:        ESLint 9 (eslint-config-next 16.2.6)
  - Git忽略:         .gitignore

五、数据库设计 (Database Schema)
================================================================================
[文件: prisma/schema.prisma]

数据源: PostgreSQL
ORM输出: lib/generated/prisma

5.1 User (用户)
  Int       id              @id @default(autoincrement())
  String    email           @unique
  String    password        (bcrypt哈希, 10轮)
  String    nickname        @unique
  String    role            @default("USER")  // "USER" | "GOLD" | "ADMIN"
  Boolean   banned          @default(false)
  DateTime? goldExpiresAt   (黄金会员到期时间)
  Int       tokenQuota      @default(10000)   (AI Token余额)
  DateTime  createdAt       @default(now())

  关联:
    files[]          -> DriveFile
    folders[]        -> DriveFolder
    generatedCdks[]  -> Cdk (作为创建者)
    redeemedCdks[]   -> Cdk (作为兑换者)
    sentMessages[]   -> PrivateMessage (作为发送者)
    receivedMessages[] -> PrivateMessage (作为接收者)
    aiConversations[] -> AIConversation
    aiUsageLogs[]    -> AIUsageLog
    aiQuota?         -> AIQuota (一对一)
    aiMemories[]     -> AIMemory
    userFriendships[] -> Friendship
    friendOf[]       -> Friendship
    createdGroups[]  -> GroupChat
    sentRequests[]   -> FriendRequest
    receivedRequests[] -> FriendRequest

5.2 DriveFolder (网盘文件夹)
  Int       id        @id @default(autoincrement())
  Int       userId    (外键 -> User, onDelete: Cascade)
  String    name
  DateTime  createdAt
  DateTime  updatedAt

5.3 DriveFile (网盘文件)
  Int       id           @id @default(autoincrement())
  Int       userId       (外键 -> User)
  Int?      folderId     (外键 -> DriveFolder, onDelete: SetNull)
  String    originalName (原始文件名)
  String    storedName   (UUID+扩展名存储)
  String    mimeType
  BigInt    size         (文件大小, 字节)
  String    storagePath
  DateTime  createdAt

5.4 Cdk (兑换码)
  Int       id          @id @default(autoincrement())
  String    code        @unique                (格式: CDK-XXXX-XXXX)
  Int       goldDays    @default(0)            (VIP天数)
  Int       tokenAmount @default(0)             (AI Token额度)
  Boolean   isUsed      @default(false)
  Int       createdBy   (外键 -> User)
  Int?      usedBy      (外键 -> User)
  DateTime? usedAt
  DateTime  createdAt

5.5 Friendship (好友关系)
  Int       id        @id @default(autoincrement())
  Int       userId    (外键 -> User)
  Int       friendId  (外键 -> User)
  DateTime  createdAt
  @@unique([userId, friendId])       // 复合唯一约束

5.6 FriendRequest (好友申请)
  Int       id         @id @default(autoincrement())
  Int       fromUserId (外键 -> User)
  Int       toUserId   (外键 -> User)
  String    status     @default("PENDING")    // PENDING | ACCEPTED | REJECTED
  DateTime  createdAt
  DateTime  updatedAt
  @@unique([fromUserId, toUserId])

5.7 PrivateMessage (私聊消息)
  Int       id         @id @default(autoincrement())
  Int       fromUserId (外键 -> User)
  Int       toUserId   (外键 -> User)
  String    content                    (最多2000字)
  Int?      emoticonId (外键 -> Emoticon)
  Int?      replyToId  (自引用 -> PrivateMessage, @relation("PrivateMessageReplies"))
  DateTime? readAt     (已读时间)
  DateTime? editedAt   (编辑时间)
  Boolean   isDeleted  @default(false)  (软删除)

六、认证系统详解 (Authentication)
================================================================================

6.1 认证流程
  1. 用户注册/登录 -> 服务端验证 -> 生成JWT (HS256, 7天) -> 设置httpOnly Cookie("token")
  2. 后续请求 -> 从Cookie读取token -> jwtVerify -> 获取userId -> 查询数据库验证用户
  3. 登出 -> 清除Cookie

6.2 关键文件
  - lib/auth.ts:       JWT创建/验证, Cookie管理, 密码哈希, getUserIdFromCookies()
  - lib/socket/auth.ts: Socket.IO认证(从cookie解析JWT, 数据库验证用户)
  - lib/captcha.ts:    图形验证码SVG生成(TTL 120秒, 排除易混淆字符)
  - lib/verification.ts: 邮箱验证码(6位随机数字, TTL 60秒)

6.3 权限级别
  - USER:  普通用户, 注册默认角色, 存储上限5GB
  - GOLD:  黄金会员(通过VIP CDK兑换), 存储上限10GB, 昵称金色流光特效
  - ADMIN: 管理员(通过create-admin.mjs创建或数据库直接修改), 可访问/admin页面

6.4 重要安全注意事项
  - ADMIN角色在CDK兑换VIP时不应被降级(已在app/api/user/cdk-redeem/route.ts修复)
  - 管理员不可被封禁(app/admin/page.tsx已限制)
  - 密码使用bcryptjs加盐10轮存储

十、工具库详解 (Library Modules)
================================================================================

10.1 认证 (lib/auth.ts)
  - createToken(userId) -> JWT (7天, HS256)

  - hashPassword(password) / verifyPassword(password, hash)

  - 使用 @prisma/adapter-pg + pg.Pool

  - sanitizeFilename(): UUID v4 + 原始扩展名
  - getStoragePath(): 路径遍历防护(path.resolve + startsWith检查)
  - deleteFile() / fileExists() / getUploadDir()
  - decodeFilename(): latin1->UTF-8中文乱码修复
  - sanitizeFolderName(): 移除 <>:"/\|?* 和不可打印字符

10.4 角色管理 (lib/roles.ts)
  - getStorageLimit(role): GOLD=10GB, 其他=5GB
  - formatLimit(role): "10 GB" / "5 GB"

10.5 B站客户端 (lib/bilibili.ts)

  - relayUrl来自 RELAY_URL 环境变量, relayKey来自 RELAY_KEY

  - IMG_PLACEHOLDER: 加载失败占位图SVG
  - resolveImageUrl(): 根据模式返回直连或代理URL
  - imgOnError/OnLoad: 记录失败/成功次数, 自动切换

  - server.ts: 初始化Socket.IO(路径/api/socketio, CORS *), 认证中间件(从cookie解析JWT)

16.2 Windows SSH 密码认证问题 (核心痛点)

在 Windows 上使用 ssh 命令进行密码认证时，会遇到以下问题：

(1) SSH_ASKPASS 环境变量干扰
  - Windows 可能设置过 SSH_ASKPASS 环境变量（值为 "powershell"）
  - 这导致 SSH 在非TTY环境下尝试调用 askpass 程序获取密码
  - 结果是密码认证永远失败，报错 "The string is missing the terminator" + "Permission denied"

(2) stdin管道传密码不可靠
  - Linux上 `echo password | ssh` 通常可以工作
  - Windows OpenSSH 不支持通过 stdin 管道传递密码
  - 系统级 SSH_ASKPASS 设置会破坏这个机制

(3) plink/sshpass 通常不可用
  - plink (PuTTY命令行) 默认未安装
  - sshpass (Linux密码中继工具) Windows上不存在

16.3 推荐部署方式：Node.js + ssh2 库

最可靠的Windows部署方式是使用 Node.js 的 ssh2 纯JS库，因为它在应用层处理SSH协议，
不受系统SSH配置影响。

部署步骤：

  (1) 在临时目录安装ssh2:
      $tmpDir = Join-Path $env:TEMP "ssh_deploy_$(Get-Random)"
      New-Item -ItemType Directory -Force $tmpDir | Out-Null
      cd $tmpDir
      npm init -y --silent | Out-Null
      npm install ssh2 --silent 2>&1 | Out-Null

  (2) 编写deploy.js脚本 (模板):
      const { Client } = require("ssh2");
      const server = {
        name: "CN",
        host: "106.14.126.214",
        port: 22,
        username: "root",
        password: "Zholv155156.",
      };
      const deployCmd = "cd /root/cloud-drive && git pull origin main && npm install && npm run build && pm2 delete cloud-drive 2>/dev/null; pm2 start 'npm run start' --name cloud-drive && pm2 save && echo === Deploy OK ===";

      const conn = new Client();
      conn.on("ready", () => {
        console.log("Connected, executing deploy...");
        conn.exec(deployCmd, { pty: true }, (err, stream) => {
          if (err) { console.log("Exec error:", err.message); conn.end(); return; }
          stream.on("close", (code) => {
            console.log("Exit:", code);
            conn.end();
            process.exit(code);
          });
          stream.on("data", (data) => process.stdout.write(data.toString()));
          stream.stderr.on("data", (data) => process.stderr.write(data.toString()));
        });
      });
      conn.on("error", (err) => { console.log("Error:", err.message); process.exit(1); });
      conn.connect({ host: server.host, port: server.port, username: server.username, password: server.password, readyTimeout: 10000 });

  (3) 运行部署:
      node deploy.js

  (4) 清理:
      用完删除临时目录即可

16.4 Git拉取常见问题

(1) 分支跟踪错误 "no tracking information"
  服务器仓库可能是 `master` 分支，而远程是 `main`。
  解决: 使用 `git pull origin main` 替代 `git pull`，明确指定分支。

(2) 本地修改冲突 "Your local changes would be overwritten"
  服务器上可能有之前agent或其他方式留下的未跟踪/已修改文件。
  解决: 在git pull前先清理:
      git checkout -- .          # 放弃所有已修改文件
      git clean -fd              # 删除所有未跟踪文件
      git pull origin main

  ★ 注意: `git clean -fd` 会永久删除未跟踪文件（包括.env等配置），
     使用前确认服务器上没有需要保留的本地文件！

16.5 PM2进程管理常见问题

(1) 进程ID变化 "Process N not found"
  `pm2 restart cloud-drive` 使用进程名而非ID，如果进程已被其他操作删除会失败。
  解决: 使用 delete + start 模式:
      pm2 delete cloud-drive 2>/dev/null
      pm2 start 'npm run start' --name cloud-drive
      pm2 save
  这样无论进程是否存在都能正常启动。

(2) 多个同名进程
  在部署失败重试后可能出现多个cloud-drive进程（ID不同）。
  解决: 使用 `pm2 delete all` 清除所有进程后再启动，或 `pm2 delete cloud-drive` 删除同名进程。

(3) 进程状态检查
  部署后务必确认:
      pm2 list          # 查看所有进程状态
      pm2 logs cloud-drive --lines 20   # 查看最近日志
